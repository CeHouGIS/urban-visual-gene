# 景观原型覆盖率试验

目标是检验：一组数量有限、可重复且语义一致的景观原型，能否解释至少80%的全景。**重建误差下降不等于语义覆盖率；80%目标目前没有得到验证。**

本轮保留3×3、7×7、15×15三个尺度，每尺度32个模板、秩4。复用主实验冻结SAE的完整稀疏激活，不提取DINO特征、不训练SAE。新增模型在各方向内部学习局部组合。

## 第一轮运行内容

1. 对现有29城、86,038个全景按1km空间块重新做约70%训练／15%开发／15%测试划分，同一块与全景四方向不跨组。比例按每城块数分配，实际全景数以`outputs/protocol.json`为准。划分固定后，测试激活不用于本轮的初始化、标准化、训练、监控和选择。
2. 只读取新训练块的原始CSR正激活，重新计算每维RMS。允许CPU做缓存统计；真实模型计算强制CUDA，无CPU推理回退。
3. 每城1个开发全景、全部四方向，固定旧模板并优化非负响应150步。保留初始响应与最佳迭代。这是无稀疏惩罚的探索性诊断，使用旧标准化以与旧编码器一致；旧模型已见过部分开发块，不能作为新模型的独立验证，也不是理论最优上界。
4. 两组新模型各训练4轮，城市均衡采样，每轮一个方向，四轮覆盖四方向。两组使用相同的训练样本初始化、随机种子、模型容量、访问顺序和学习率。`balanced_reference`使用原正/零误差及稀疏惩罚；`energy_warmup`使用每图能量NMSE，并在首轮逐步加入稀疏惩罚。第三轮起隐藏20%patch并增加隐藏恢复目标。该试验比较两套完整设置，不能单独归因于某一项调整。
5. 每城固定4个开发全景、四方向选择checkpoint；随后对全部开发全景的四方向评分。分别记录逐方向、四方向全部、任一方向达到某个重建要求的比例，记录响应质量与有效模板数。四轮为筛选试训，尚非最终收敛结果。
6. 输出重建质量曲线和290个开发全景的待人工核查表。语义一致性、缺失内容与冗余等标签保持为空，待核查后固定语义判据。最终测试保持封存，后续再开展两名评审的独立抽样核查、区间估计、多种子及对照。

冻结SAE已见过部分新开发／测试图像，划分仅针对新增原型层。随机相邻空间块仍可能相关；正式实验应评估缓冲距离或整城留出。模板总量调参仍是后续待办。

## 运行和输出

```bash
python -u -m experiments.vitl30_prototype_coverage.code.run --device cuda:2
python -m pytest -q experiments/vitl30_prototype_coverage/tests
```

后台流程使用独占锁，保存阶段状态、每100步训练checkpoint、逐方向诊断和逐城市评分。显存不足时等待，CUDA OOM后从已有产物恢复，最多重试10次；其他错误明确失败。默认需1600MiB可用显存，PyTorch缓存上限1280MiB，不干扰现有Qwen任务。

`outputs/`保存完整协议、清单、训练校准、诊断、模型、开发评估及人工核查表；`results/`保存完成后的简报与曲线。旧原型实验与原图不改动。项目进度侧栏跟踪本轮计算，但人工语义核查另列未完成。

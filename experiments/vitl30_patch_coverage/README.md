# 逐图80% patch覆盖的景观原型实验

目标：学习有限的共享景观模板，使**每张方向图像至少80%的有效patch满足固定解释质量要求**。分别报告逐图达标比例、最差及低分位图像覆盖率、全景四方向全部达标比例。全数据平均patch覆盖率不能代替逐图要求。当前是可行性试验，不能预先保证所有图像都能达标。

## 输入与划分

复用主实验ViT-L、28×28、W4096/K32的完整SAE稀疏激活，不重新提取DINO特征，不重训SAE。四方向的表征已经包含panorama context，新原型模型在各方向内部学习局部组合，不在拼接边界做卷积。

29城市、86,038个全景（344,152张方向图像）；Moscow原图映射未核实，暂不纳入。复用`vitl30_prototype_coverage`的新1km空间块划分与训练集RMS：训练60,233全景／240,932图，开发12,755全景／51,020图，测试13,050全景／52,200图。同一空间块和全景四方向不跨组。本轮最终测试保持封存，仅在训练与开发集评分。冻结SAE曾见过部分开发和测试图像，因此空间留出只适用于新增原型层。

## 固定的计算判据

输入按训练集每维正激活RMS标准化并截断至8。每个patch的激活向量为a，重建为â。

```
eligible = ||a||² > 1e-8
patch_NMSE = ||â - a||² / max(||a||², 1e-8)
covered = eligible AND patch_NMSE <= 0.5
image_pass = eligible_count > 0 AND covered_count >= ceil(0.8 * eligible_count)
```

784个patch全部有效时，一张图至少需要628个patch达标。有效patch仅由目标激活决定，模型不能通过重建或预测的置信度剔除困难patch。无有效patch的图像计为未达标，另外公开无效patch数量；无效patch上的虚假激活仍受到全图重建惩罚。

**NMSE≤0.5是预先固定的探索性重建门槛，相当于相对零向量基线至少减少50%的平方误差，尚不是经过语义核查的解释标准。**80%是patch数量比例，0.5是每个patch的质量门槛，不能混淆或调整门槛来凑80%。输出保留人工语义核查待办，重建达标不能直接声称景观含义已被解释。

## 模型与训练

保留多尺度非负卷积原型自编码器：3×3、7×7、15×15，各32个候选模板，共96个；每个模板秩4。数量调参16／32／64仍独立登记待办。本轮不加入强化学习。

以sigmoid((0.5−patch_NMSE)/T)构造软覆盖，T在前两轮由0.25降至0.1。对每张图分别计算`relu(0.8−soft_coverage)²`后取平均，权重5；同时优化逐图能量NMSE、权重0.1的log1p patch误差，以及首轮预热的响应L1和模板组成惩罚。覆盖高的图像不能抵消覆盖低的图像。硬覆盖始终独立计算和报告，不把软覆盖当实际达标。

训练8轮，batch8，AdamW，初始学习率0.001，种子42。城市均衡，每轮访问一个方向，8轮中每方向两次；本轮不额外隐藏patch。训练样本初始化模板。每轮在固定每城4全景、四方向的464张开发图上监控；按逐图达标比例优先、平均逐图硬缺口其次、平均覆盖和NMSE再次选择checkpoint，之后完整评分训练和开发集。模板数固定时达不到目标，也作为可行性结果如实记录。

## 运行与输出

```bash
python -m pytest -q experiments/vitl30_patch_coverage/tests
python -u -m experiments.vitl30_patch_coverage.code.run --device cuda:3
```

真实数据计算只在GPU运行。默认需1600MiB空闲显存，PyTorch缓存上限1280MiB；不足则等待，OOM最多重试10次，从每100步checkpoint和逐城市评分断点恢复。独占锁防止重复启动，非OOM错误明确失败。GPU2的两组覆盖率试训保留为重建目标对照。

`outputs/protocol.json`固定数据、标准化、SAE身份、模型和门槛；`model/`保存训练、初始开发表现和逐轮监控；`evaluation/{train,dev}/`保存每张图的计数、原图路径、逐patch二值覆盖图和未达标清单；`results/`保存分布曲线、达标比例、五个覆盖分位数的原图叠加实例及报告。绿色达标、红色未达标、灰色无有效激活。网站侧栏跟踪训练和评分，语义核查单独列为未完成。

## 冻结模板响应诊断

逐图覆盖未达标后，用同一个最佳checkpoint与开发集29城各1全景的四方向，共116张方向图，冻结模板，只优化非负响应图。分别试仅降全图能量NMSE和直接优化逐图覆盖损失；保存每条路线起点、过程、最佳硬覆盖和有限步结果。这个无响应稀疏惩罚的搜索比较宽松，但不是表达能力的理论上限，也不证明语义有效。测试集不参与。结果见`results/response_refit_README.md`。

## 当前模型的逐原型图像实例

```bash
python -u -m experiments.vitl30_patch_coverage.code.gallery --device cuda:1 --examples 8
```

只检索开发集12,755全景的51,020方向图。排名阶段复用同一个编码器，在GPU上计算每模板、每图的空间峰值；逐城市保留16个候选，随后选择不同全景点位并优先保持城市多样性。float32下核验单个峰值响应为正，且移除该响应使全图重建SSE增加，才保留为实例。保存原图、局部模板贡献热图、模板支持范围裁剪和25%峰值贡献掩膜。掩膜不是语义分割，实例尚需语义一致性核查。

结果绑定`model/best.pt`和覆盖实验身份，保存到`outputs/gallery/`；逐城市排名和逐模板渲染均可恢复。当前模型96个槽位中66个有实例，各8个，共528例；3×3／7×7／15×15尺度分别15／26／25个模板有正响应，另外30个在完整开发集没有正响应。每个有实例模板覆盖至少4座城市，未发生原图读取失败。不得使用较早`vitl30_multiscale_prototypes`模型的同编号图像替代这些实例。最终测试集保持封存。
